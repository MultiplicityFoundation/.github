3) Multiplic routing blueprint (registry + wildcard safety)
Principle
Even with wildcard DNS, you must not “serve real tenant content” unless the tenant is provisioned.

ADR-001: no domain may be served without multiplic.json entry. citeturn2search3
But if you go wildcard tenants, you’ll likely need either:

a wildcard entry in multiplic.json, or
a catch-all site that serves the tenant shell and lets the app show “Not provisioned”.
We need the actual multiplic.json schema to pick the exact approach.

Two safe patterns (we’ll choose based on your schema)
Wildcard domain → tenant shell, and tenant shell checks provisioning via API:
If unknown tenant: show “Tenant not provisioned”
Explicit per-tenant entries, still mapping to the same tenant shell folder:
finance.aiistech.com entry exists
healthcare.aiistech.com entry exists
Unknown tenant: Multiplic serves fallback site / 404
Pattern (2) matches ADR-001 strictly; pattern (1) requires schema support for wildcard entries.
