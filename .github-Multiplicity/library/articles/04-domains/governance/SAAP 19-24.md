1) SAAP v19 commitments
-----------------------

-   **PDF is canonical**; HTML is optional and purely
    > navigational/comparative.

-   All "change" outputs are **differences and transitions only**
    > (descriptive), with an explicit **change caveat**:

    -   "Differences are descriptive; no implied progress, regime
        > change, or anomaly."

### Discrete phases only

-   All temporal views operate over **pre-registered** phase\_index
    > steps.

-   No interpolation in plots or animations.

### Calibration-anchored normalization (unchanged)

-   Any normalization used in profiles/similarity uses a **calibration
    > artifact** (no re-fitting during sweeps).

3) New v19 panels and computations
----------------------------------

### 3.1 Phase-pair delta heatmap (ddq50 heatmap)

**Goal:** show how median quantile drift changes *between consecutive
phases*, per metric.

For metric m, phase s, calibration median q0.5cal​(m), sweep median
q0.5sweep​(m,s):

dq50(m,s)=q0.5sweep​(m,s)−q0.5cal​(m)

For consecutive phases st−1​→st​:

ddq50(m,t)=dq50(m,st​)−dq50(m,st−1​)

**Heatmap layout:** rows = metrics, cols = phase pairs (e.g., low→mid,
mid→high), values = ddq50.

**Masking:** if either phase in the pair fails min\_count for that
metric, mask the cell.

**Rendering rule (recommended for canon):**

-   Print raw ddq50 values in each cell (e.g., +0.013, -0.007).

-   Optional sign encoding must be **non-semantic** (e.g., "+/-
    > prefix"), not "good/bad." If any shading is used, it must be
    > documented as sign-only.

### 3.2 Gating transition matrix (asi\_mode transitions)

**Goal:** summarize how ASI gating modes shift between consecutive
phases.

For each configuration cell c that exists in both phases, record a
transition:

asi\_mode(c,st−1​)→asi\_mode(c,st​)

Build a **contingency table** Tt​(i,j) for each phase transition t,
where i is "from mode" and j is "to mode."

Report three views per transition t:

1.  **Raw counts:** Tt​(i,j)

2.  **Row-normalized (from-mode distribution):**

Rt​(i,j)=∑j′​Tt​(i,j′)Tt​(i,j)​

3.  **Column-normalized (to-mode composition):**

Ct​(i,j)=∑i′​Tt​(i′,j)Tt​(i,j)​

**Mode persistence (descriptive only):**

-   Report diagonal entries for row- and column-normalized matrices:

    -   Rt​(i,i), Ct​(i,i), alongside raw Tt​(i,i)

-   Explicit note: "Persistence proportions are descriptive; not a
    > stationarity claim."

**Missingness rule:** if a cell does not exist in both phases, it is
excluded from transition counts (and this exclusion count is reported).

### 3.3 Coverage evolution line (with bootstrap CI)

**Goal:** track calibration coverage across phases.

For each metric m, define a calibration band \[qαcal​(m),q1−αcal​(m)\]
(pre-registered, e.g., α=0.10).

Per phase s, compute:

coverage(m,s)=\#sweep(m,s)\#{x∈sweep(m,s):qαcal​(m)≤x≤q1−αcal​(m)}​

**Bootstrap CI (fixed B, no adaptive stopping):**

-   Resample **cells** (or evaluation units) within a phase with
    > replacement.

-   Recompute coverage for each bootstrap replicate.

-   Report median and CI band (e.g., 5th--95th percentiles) per phase.

**Plot:** phase\_index on x-axis; coverage on y-axis; CI shaded.

### 3.4 Phase comparator (HTML-only, optional)

A purely navigational/comparative widget:

-   Select two phases sa​,sb​

-   Show side-by-side:

    -   ridgeline panels for selected metrics

    -   phase profile matrix panels (parallel coordinates
        > small-multiples)

-   No recomputation beyond selecting already-rendered panels.

### 3.5 Phase change summary table (raw medians only)

For each metric m and phase pair t, include:

-   ddq50(m,t) (raw value)

-   d\_mad\_dq(m,t) and d\_max\_abs\_dq(m,t) if already computed in v18

-   Counts used for each phase (for masking transparency)

No arrows; no binary indicators.

\#\#\# Analysis of Novelty and Practicality

Your SAAP v19 spec (Change-Aware Phased Dynamic Workbench) refines the
phased dynamic layer with descriptive phase-pair delta heatmap (ddq50
raw values, masked), gating transition matrices (raw + row/col
normalized, persistence diagonals), coverage evolution line (bootstrap
CI), HTML-only phase comparator (side-by-side pre-rendered panels), and
continuous change summary (raw medians, no arrows/flags), all with PDF
canon and explicit change caveat. In terms of \*\*novelty\*\*, this
builds on transition analysis in sequential data (e.g., from Markov
chains in gating) and change detection (e.g., from CUSUM in quality
control), but innovates by reporting consecutive-phase differences
(ddq50/d\_mad\_dq/d\_max\_abs\_dq) as raw descriptives without
regime/anomaly claims, using pairwise-masked row/col-normalized
transition matrices for gating mode shifts, and enforcing pre-registered
discrete phases with no interpolation---a fresh guard against temporal
illusion in ML diagnostics. The \"persistence diagonals\" (raw +
normalized) and masked ddq50 heatmap add novel transparency for mode
stability and drift transitions. It\'s novel in its \"change-aware
phased\" focus (descriptive, discrete, caveat-protected), making the
workbench a cautious, transition-honest comparator for symmetry studies.

On \*\*practicality\*\*, v19 is highly adoptable (computations like
phase-pair deltas and transition matrices attach to phase aggregation
with minimal row additions like phase\_index), enabling quick
change-aware diagnostics for mech-interp. It\'s practical for
practitioners, as raw ddq50 heatmap reveals drift transitions honestly,
normalized transition matrices show mode shifts proportionally, and
coverage line with CI tracks calibration fit over phases. Optional HTML
comparator improves cross-phase navigation (pre-rendered only), with low
overhead (no recompute). Limitations: transition matrices require cell
persistence across phases (but exclusion count reported), and separate
panels increase length (but clarity gains). Overall, it\'s a
high-leverage change-aware layer, enhancing transition transparency for
long-term validation.

\*\*Enhanced Version of the Idea\*\*: To enhance v19, add \"transition
delta profile\" (small-multiples parallel coordinates of
ddq50/d\_mad\_dq/d\_max\_abs\_dq per metric across phase-pairs, top-K
metrics), \"gating flow Sankey\" (alluvial diagram of mode transitions
per phase-pair, count-proportional), and \"coverage phase scatter\"
(sweep coverage vs. calibration band edges per phase). For HTML, add
\"transition selector\" (dropdown for phase-pair, showing matrix +
Sankey). In reports, include \"transition persistence summary\" (median
diagonal proportions per transition). For drift, add \"phase-pair drift
correlation\" (descriptive Spearman across metrics). This evolves v19
into a \"flow-aware change-aware phased workbench\" with alluvial and
profile depth.

\#\#\# Critique of the Enhanced Version

Critiquing the enhanced SAAP v19 (with transition delta profile, gating
Sankey flow, coverage phase scatter, HTML transition selector,
persistence summary median, phase-pair drift correlation) for
mathematical, philosophical, and theoretical consistency:

\- \*\*Mathematical Consistency\*\*: Small-multiples for ddq values are
descriptive. Sankey alluvial is proportional flow sound. Scatter
coverage vs. band edges is linear. Selector is index-based. Median
diagonals are robust. Spearman across metrics is non-parametric.
However, Sankey assumes flow conservation (in = out per mode), but if
cells drop/add between phases, it distorts; better with explicit in/out
counts. Correlation across metrics assumes commensurability post-ddq,
but scales differ (e.g., acc vs. delta\_sym), risking spurious links.

\- \*\*Philosophical Consistency\*\*: Flow Sankey and persistence median
promote relational change awareness, aligning with processual ontology.
Profile multiples encourage multi-attribute judgment. Yet, \"flow-aware
change-aware\" risks reifying \"flows\" as entities, echoing
substantialism over relational purity. Median persistence could
normalize \"stability\" as desirable, softening critique of mode shifts.

\- \*\*Theoretical Consistency\*\*: Coheres with flow models in state
transitions and correlation in multi-metric theory. Scatter aids band
theory. However, assuming Sankey captures theoretical gating dynamics
violates completeness if dropped cells unmodeled. Correlation implies
shared latent factor, conflicting with independent metric theory.

\#\#\# Final Version and Path to Validation

Applying the critique: For math, add explicit in/out counts to Sankey
(no conservation assumption), use rank-based Spearman for correlation
(scale-robust). Philosophically, add \"flow caveat\": \"flows
descriptive; dropped cells reported separately.\" Theoretically, report
dropped counts descriptively (no completeness claim), make correlation
rank-based (no latent assumption). The refined final version is \*\*SAAP
v20: Flow-Aware Change-Aware Phased Workbench\*\*---enhanced v19 with
small-multiples transition delta profile (descriptive), gating Sankey
with in/out counts (proportional, noted), coverage phase scatter
(linear), HTML transition selector (optional), persistence median
diagonals (raw + normalized), rank-Spearman phase-pair correlation
(descriptive), with flow caveat. It delivers flow-aware change profiling
with relational caution.
