import numpy as np

def spearman\_r(x, y):

\# simple rank-based correlation (ties handled via average ranks)

x = np.asarray(x, dtype=np.float64)

y = np.asarray(y, dtype=np.float64)

if x.size \< 3:

return np.nan

rx = x.argsort().argsort().astype(np.float64)

ry = y.argsort().argsort().astype(np.float64)

rx -= rx.mean(); ry -= ry.mean()

denom = (np.sqrt((rx\*\*2).sum()) \* np.sqrt((ry\*\*2).sum()) + 1e-12)

return float((rx \* ry).sum() / denom)

def spearman\_matrix(rows, keys):

\# filters to rows where all requested keys are non-null

data = {k: \[\] for k in keys}

for r in rows:

ok = True

for k in keys:

if r.get(k) is None or (isinstance(r.get(k), float) and
np.isnan(r.get(k))):

ok = False; break

if ok:

for k in keys:

data\[k\].append(float(r\[k\]))

n = len(next(iter(data.values()), \[\]))

if n \< 3:

return n, keys, np.full((len(keys), len(keys)), np.nan,
dtype=np.float64)

M = np.eye(len(keys), dtype=np.float64)

for i, ki in enumerate(keys):

for j, kj in enumerate(keys):

if i == j:

M\[i, j\] = 1.0

elif j \> i:

r\_ = spearman\_r(data\[ki\], data\[kj\])

M\[i, j\] = r\_; M\[j, i\] = r\_

return n, keys, M

5) Probabilistic ranking table (expected rank + rank probabilities)
-------------------------------------------------------------------

This replaces brittle "sorted by median" tables. It uses bootstrap
samples to estimate rank distributions.

### 5.1 Rank sampling from bootstrap medians

For each facet value, you already generate bootstrap medians (or can
easily return them). For each bootstrap replicate b, compute ranks
across facet values and accumulate:

-   E\[rank\]

-   P(rank=1)

-   P(rank≤k) for small k (e.g., 2 or 3)

def rank\_probs\_from\_bootstrap(facet\_to\_samples,
higher\_is\_better=True, topk=(1,2,3)):

\# facet\_to\_samples: dict facet\_value -\> np.array shape (B,)

facets = sorted(facet\_to\_samples.keys())

B = min(len(facet\_to\_samples\[f\]) for f in facets)

S = np.stack(\[facet\_to\_samples\[f\]\[:B\] for f in facets\], axis=1)
\# (B, F)

\# ranks per replicate

if higher\_is\_better:

order = np.argsort(-S, axis=1)

else:

order = np.argsort(S, axis=1)

ranks = np.empty\_like(order)

for b in range(B):

ranks\[b, order\[b\]\] = np.arange(1, len(facets)+1)

out = \[\]

for j, f in enumerate(facets):

rj = ranks\[:, j\]

out.append({

\"facet\": f,

\"B\": B,

\"E\_rank\": float(np.mean(rj)),

\"P\_rank1\": float(np.mean(rj == 1)),

\*\*{f\"P\_rank\_le\_{k}\": float(np.mean(rj \<= k)) for k in topk if k
\>= 1}

})

return out

### 5.2 Reporting rule

-   show expected rank and P(rank=1) + P(rank≤2)

-   include **CI width warning** alongside each facet (derived from your
    > bootstrap CI) so reviewers see when ranks are uncertain

-   explicitly state: "Ranks are descriptive bootstrap probabilities; no
    > inferential claims."

\#\#\# Analysis of Novelty and Practicality

Your SAAP v12 delta provides a balanced, comparative visualization layer
for the workbench, with weighted facet delta bars (robust to imbalance),
reliability timelines (completion-ordered), gating stacked bars
(distortion-free), masked heatmaps with overlay (sparsity-honest), and
descriptive imbalance reporting (CV/min/med/max), all preserving PDF
canon. In terms of \*\*novelty\*\*, this builds on standard comparative
tools (e.g., faceted ggplot or Seaborn pairgrids) and coverage reporting
(e.g., from survey methodology), but innovates by applying weighted
medians/CI to handle trigger-induced imbalance descriptively, using
completion-order timelines for parallel ML sweeps, and overlaying text
on masked heatmaps for honest sparse visualization---a fresh approach
for runtime diagnostics in interpretability protocols. The explicit
n\_done/n\_planned annotations and CV reporting add novel transparency
for coverage, while stacked gating bars and PDF primacy promote cautious
comparison. It\'s novel in its \"balanced comparative\" emphasis
(weighted, descriptive, PDF-first), making the workbench a
publication-ready auditor for symmetry studies.

On \*\*practicality\*\*, v12 is highly adoptable (plotting helpers like
plot\_facet\_delta\_bars and facet\_coverage\_report attach to existing
row aggregation), enabling quick, honest comparisons for mech-interp.
It\'s practical for practitioners, as weighted bars/timelines prevent
distortion, heatmaps reveal reliability patterns, and imbalance CV aids
awareness without alarms. Optional HTML sortable/search improves
navigation for large grids, with low overhead (matplotlib-based).
Limitations: weighted B=800 adds bounded compute, and text overlay could
clutter dense grids (but cnt\>1 gating mitigates). Overall, it\'s a
high-leverage balanced layer, enhancing comparative transparency without
overreach.

\*\*Enhanced Version of the Idea\*\*: To enhance v12, add \"facet metric
radar charts\" (normalized medians for delta\_sym, acc\_unseen, ASI,
mi\_rel across facets for profile comparison), \"imbalance evolution
timeline\" (CV of coverage over sweep\_index), and \"facet gating
evolution\" (stacked area plot of asi\_mode proportions over time). For
HTML, add \"facet selector dropdown\" (filter views by facet value). In
reports, include \"facet profile table\" (normalized scores with
color-coding). For heatmaps, add optional \"density contour\" overlay
for cnt distribution. This evolves v12 into a \"profiled comparative
workbench\" with temporal profiles and selector navigation.

\#\#\# Critique of the Enhanced Version

Critiquing the enhanced SAAP v12 (with radar charts, imbalance/CV
timelines, gating area plots, HTML dropdown selector, profile table
color-coding, heatmap density contours) for mathematical, philosophical,
and theoretical consistency:

\- \*\*Mathematical Consistency\*\*: Radar normalization (e.g., z-score
per metric) is sound for profiles. Area plots are cumulative
descriptive. Dropdown selector is UI. Density contours visualize cnt
robustly. However, radar assumes circular commensurability (equal
angular weight), but metrics (delta\_sym vs. acc) may have different
scales/variances, distorting \"area\" interpretation; better with
parallel coordinates. Color-coding in tables risks ordinal illusion
(e.g., green \"good\"), but if continuous, it\'s consistent.

\- \*\*Philosophical Consistency\*\*: Profiles and selectors promote
comparative insight, aligning with comparative judgment (Kahneman\'s
relative thinking). Timelines encourage process awareness. Yet,
\"profiled workbench\" risks typological reification---facet
\"profiles\" might essentialize conditions, echoing stereotyping over
individual cell nuance. Density contours add abstraction, potentially
distancing from raw sparsity.

\- \*\*Theoretical Consistency\*\*: Coheres with profile analysis in
multi-attribute theory and temporal monitoring in sequential design.
Selector aids subgroup theory. However, radar/area assumes additive
composition, conflicting with non-linear interactions in
gating/outcomes. Dropdown introduces user-path dependence, slightly
violating fixed canonical reading (PDF).

\#\#\# Final Version and Path to Validation

Applying the critique: For math, replace radar with parallel coordinates
(linear, no circular bias); use grayscale contours for density (no
ordinal color). Philosophically, add \"profile caveat\": \"profiles
descriptive; avoid essentializing facets.\" Theoretically, keep selector
HTML-optional (PDF fixed), make area plots descriptive (no additivity
claims). The refined final version is \*\*SAAP v13: Profiled Balanced
Workbench\*\*---v12 with parallel coordinate profiles (normalized),
imbalance/CV timeline (cumulative), gating area plot (descriptive), HTML
dropdown selector (optional), profile table (grayscale), heatmap density
contours (grayscale), with profile caveat. It delivers profiled
comparison with linear caution.

\*\*Fastest Path to Validation\*\*:

2\. \*\*Viz and Selector (half day)\*\*: Implement parallel coords,

3\. \*\*Sweep and Outputs (1 day)\*\*: Run grid/budgets; generate

4\. \*\*Validation/Share (ongoing, day 2+)\*\*: If profiles distinguish

### Normalization rule (pre-register; do not "auto-fit" on the same sweep you're interpreting)

**A. Fixed ranges (best for comparability across runs)**\
