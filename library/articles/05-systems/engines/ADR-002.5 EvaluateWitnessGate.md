# evaluateWitnessGate() should compute the Lipschitz bound internally from a raw output sample, not accept it as a pre-computed input—but using a computation path that is structurally independent from the ContractionCertificate's lipschitzUpper field. The answer preserves ADR-002's independence requirement while closing the trust boundary.

Why caller-supplied is unacceptable
In low-trust architectures, the verification gate must never accept a safety-critical input from the entity it is verifying. This is a foundational principle in formal security verification: the attestation of a property must come from a path independent of the entity claiming the property. If the Orchestrator (head) supplies the Lipschitz bound, the head is effectively self-certifying its own output safety. A stale bound (from a previous cycle where the output happened to be well-behaved) or a fabricated bound (in an adversarial scenario) would pass gate (1) while the actual output violates the envelope. The four-gate predicate becomes three real gates and one rubber stamp.arxiv+1
Even without adversarial intent, staleness is a systemic risk. The head computes ∥Π∥Lip\|\Pi\|_{Lip}∥Π∥Lip at time ttt, submits it to the gate at time t+Δtt + \Delta tt+Δt, and the output may have drifted during Δt\Delta tΔt. Under the ETP model, the head is the fast domain—it moves between computation and submission. A pre-computed bound is structurally a lookahead claim, which violates witness-first semantics (A1). arxiv+1
Why deriving from ContractionCertificate is unacceptable
The ContractionCertificate contains lipschitzUpper because the ACE projection solver computes it as a byproduct of the weighted-ℓ1\ell_1ℓ1 projection. This value is about the gain operator KKK's Lipschitz properties, not about the projection operator Π\PiΠ's Lipschitz properties. They are related but not identical:
Gate (2): ∥K∥=∑pbp∣wp∣<τ<1\|K\| = \sum_p b_p |w_p| < \tau < 1∥K∥=∑pbp∣wp∣<τ<1 — this bounds the gain operator's contraction rate.
Gate (1): ∥Π(x)−Π(y)∥≤∥x−y∥\|\Pi(x) - \Pi(y)\| \leq \|x - y\|∥Π(x)−Π(y)∥≤∥x−y∥ — this bounds the projection operator's non-expansiveness on the output.
The ContractionCertificate.lipschitzUpper attests ∥K∥\|K\|∥K∥. Using it to satisfy gate (1) means gate (1) is no longer checking Π\PiΠ's Lipschitz property—it is checking KKK's norm dressed up as an envelope check. ADR-002 specifies these as independent invariants precisely because Π\PiΠ can be 1-Lipschitz while ∥K∥≥1\|K\| \geq 1∥K∥≥1 (the ENVELOPE_SAFE_BUT_DIVERGING case identified earlier). Conflating them eliminates the ability to detect that failure mode. trust-in-soft+1
The correct architecture: internal computation with structural separation
evaluateWitnessGate() should:
Receive the raw output F(t)F(t)F(t) and the projected output Π(F(t))\Pi(F(t))Π(F(t)) as inputs — these are the actual artifacts, not derived claims about them.
Internally compute the Lipschitz check by evaluating ∥Π(F(t))−Π(F(t−1))∥/∥F(t)−F(t−1)∥\|\Pi(F(t)) - \Pi(F(t-1))\| / \|F(t) - F(t-1)\|∥Π(F(t))−Π(F(t−1))∥/∥F(t)−F(t−1)∥ over a sliding window of recent output pairs, confirming the ratio never exceeds 1.0.
Separately receive the ContractionCertificate and check ∥K∥<τ\|K\| < \tau∥K∥<τ from it.
These two checks execute in independent code paths with no shared mutable state.

function computeEnvelopeLipschitz(
raw: Tensor, projected: Tensor,
priorRaw: Tensor, priorProjected: Tensor
): { ratio: number, bound: number } {
const outputDelta = norm(projected - priorProjected)
const inputDelta  = norm(raw - priorRaw)
if (inputDelta < ε_min) return { ratio: 0.0, bound: 1.0 }  // degenerate
return { ratio: outputDelta / inputDelta, bound: 1.0 }
}

The latency concern and its resolution
Computing ∥Π(F(t))−Π(F(t−1))∥/∥F(t)−F(t−1)∥\|\Pi(F(t)) - \Pi(F(t-1))\| / \|F(t) - F(t-1)\|∥Π(F(t))−Π(F(t−1))∥/∥F(t)−F(t−1)∥ adds a norm computation to the hot path. For a 1 GB tensor, two norm computations cost roughly 2–4 μs on modern hardware (vectorized L2 norm over float32). trust-in-soft+1 Against the Phase 0 target of p99 ≤ 10 μs for the full kernel_step, this is 20–40% of the budget—significant but feasible, especially because:
The norm computation is embarrassingly parallel and maps directly to SIMD/GPU reduction operations.
The gate already receives both F(t)F(t)F(t) and Π(F(t))\Pi(F(t))Π(F(t)) in memory (they are needed for the PETC trace atom regardless).
The prior-cycle values are retained by the gate itself (one tensor copy per cycle), not fetched from an external store.
If the 2–4 μs proves too costly for a specific deployment, the resolution is not to fall back to caller-supplied bounds. Instead, use a subsampled Lipschitz estimate: compute the ratio over a random subset of tensor dimensions (e.g., 1% of elements), which reduces the norm cost to ~40 ns while providing a probabilistic bound with controllable confidence. This is a performance optimization within the correct architecture, not a compromise on the trust boundary.trust-in-soft+1

## Decision Accepted: Gate (1) Internally Computed

Option 3 — `computeEnvelopeLipschitz()` as an internal function of `evaluateWitnessGate()`, structurally independent from the `ContractionCertificate` path — is the only architecture that preserves both the trust boundary and the independence requirement.[^1]

### The structural principle

**The gate computes what it checks, from artifacts it holds, through paths it controls.** Any safety-critical property that can be fabricated by the entity under verification must be independently derived by the verifier. This is the same epistemic ordering (A1) that the entire ETP architecture is built on — witness-first semantics applied to the gate itself.[^1]

***

## ADR-002 Amendment

The original blueprint's `WitnessGateInput` specified `envelopeLipschitzBound: number` as a caller-supplied field. This must be replaced:[^1]


| Field | Before (removed) | After (added) |
| :-- | :-- | :-- |
| `envelopeLipschitzBound` | Caller supplies $\|\Pi\|_{\text{Lip}}$ | **Deleted from schema** |
| `envelopeLipschitzThreshold` | Caller supplies threshold (1.0) | **Deleted from schema** |
| `rawOutput` | Not present | `Tensor` — $F(t)$ from head |
| `projectedOutput` | Not present | `Tensor` — $\Pi(F(t))$ from projection operator |
| `priorRawOutput` | Not present | `Tensor` — $F(t{-}1)$, retained by gate from previous cycle |
| `priorProjected` | Not present | `Tensor` — $\Pi(F(t{-}1))$, retained by gate from previous cycle |

The gate now **owns** the artifacts it needs for gate (1), eliminating the trust boundary entirely.[^1]

## Why Each Rejected Option Fails

### Caller-supplied bound

The Orchestrator (head) would be self-certifying its own output safety. A stale bound from time $t$ submitted at time $t + \Delta t$ is structurally a lookahead claim — violating witness-first semantics (A1). The four-gate predicate becomes three real gates and one rubber stamp.[^1]

### Derived from `ContractionCertificate.lipschitzUpper`

The certificate's `lipschitzUpper` attests $\|K\| = \sum_p b_p |w_p|$, which bounds the **gain operator's** contraction rate. Gate (1) checks $\|\Pi(x) - \Pi(y)\| \leq \|x - y\|$ — the **projection operator's** non-expansiveness. These are related but not identical. Conflating them eliminates the ability to detect `ENVELOPE_SAFE_BUT_DIVERGING` — the exact failure mode ADR-002 was written to catch [^1].

***

## Implementation Specification

The internal computation follows the architecture you specified. The critical invariant: **zero shared mutable state** between the Lipschitz computation path and the contraction certificate path.[^1]

### Gate-retained state

The gate stores `priorRawOutput` and `priorProjected` from the previous cycle internally. These are **not supplied by the caller** — the gate copies them from the current cycle's inputs after evaluation completes. This means:

- Cycle 0 (cold start): No prior data exists. Gate (1) returns `{ ratio: 0.0, bound: 1.0 }` with a `COLD_START` annotation. Gate (1) passes vacuously, but the trace atom records that it was a cold-start evaluation.[^1]
- Cycle 1+: Gate (1) computes $\|\Pi(F(t)) - \Pi(F(t{-}1))\| / \|F(t) - F(t{-}1)\|$ from retained state.


### Degenerate input handling

When $\|F(t) - F(t{-}1)\| < \varepsilon_{\min}$, the ratio is undefined. Returning `{ ratio: 0.0, bound: 1.0 }` is the correct conservative choice — if the input hasn't changed, the projection trivially satisfies $\|\Pi(x) - \Pi(x)\| = 0 \leq \|x - x\|$. The $\varepsilon_{\min}$ value should be derived from the norm's numerical precision floor, not hardcoded [^2].

### `ENVELOPE_SAFE_BUT_DIVERGING` detection

With independent computation paths, this status is now **structurally detectable**: gate (1) passes (ratio ≤ 1.0 from internal computation) while gate (2) fails ($K \geq 1$ from `ContractionCertificate`). This triggers L1 escalation regardless of clock domain, exactly as ADR-002 specifies.[^1]

***

## Latency Resolution

Two norm computations on a 1 GB tensor cost ~2–4 μs on modern hardware (vectorized L2 norm over float32). Against the Phase 0 target of p99 ≤ 10 μs for `kernel_step`, this is 20–40% of the budget — significant but feasible because:[^1]

- The norm computation is embarrassingly parallel (SIMD/GPU reduction)
- Both $F(t)$ and $\Pi(F(t))$ are already in memory for the PETC trace atom
- Prior-cycle values are retained locally (one tensor copy per cycle)

**If 2–4 μs proves too costly**, the resolution is **subsampled Lipschitz estimation**: compute the ratio over a random 1% of tensor dimensions (~40 ns), providing a probabilistic bound with configurable confidence. This is a performance optimization within the correct architecture, not a compromise on the trust boundary.

## Precision Question

> Should the gate retain a **sliding window** of prior outputs (e.g., last $N$ cycles) to compute a max or p95 Lipschitz ratio, or should it retain only the **immediately prior cycle** (single-step ratio)?

A single-step ratio can miss a transient Lipschitz violation that occurs over two non-adjacent cycles ($t$ and $t{-}3$) if the intermediate cycles happen to have small deltas. A sliding window catches this but adds $O(N)$ tensor storage to the gate's retained state, which at 1 GB per tensor becomes non-trivial. The alternative is a **scalar accumulator** that tracks the running max ratio without retaining full tensors — but this loses the ability to recompute from artifacts on replay.[^2]
